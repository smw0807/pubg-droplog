## 2026-10-05 이벤트 거리 표시

타임라인의 기절·처치·피해 이벤트에서 무기명 뒤에 `거리 57m`처럼 정수 미터를 표시한다. 저장된 행위자·대상의 XYZ 좌표로 높이를 포함한 직선거리를 계산하고 cm를 m로 변환한다. 처치는 기존 제목과 같은 킬 획득자 기준이며 마무리 공격자로 대체하지 않는다. 소생, 역할·좌표·높이 누락, 비정상 좌표는 거리를 생략하고 유효한 0m는 표시한다. 좌표 기준이라는 안내를 함께 제공하며 원본 공격 거리로 해석하지 않는다. 기존 리포트를 재분석하거나 API·저장 스키마를 변경하지 않는다.

- 실제 론도 리포트의 주요 사건 46개 중 소생 2개를 제외한 **44개**에 거리 표시를 확인했다. 첫 기절 **57m**, 다음 처치 **72m**이며 피해 필터 첫 50개 중 45개에도 거리가 표시된다. 실제 브라우저에서 카드·설명·지도 선택의 배치를 확인했다.
- 거리 단위 테스트 **14개 통과**: cm→m 변환, 높이와 음수 고도, 0m, 소생 제외, 누락·비정상 좌표, 처치자와 마무리 공격자 구분.
- 별도 demo 서버 Chromium **9개 통과(14.9초)**: 새 거리 표시·필터 회귀 1개와 기존 지도/타임라인 선택·필터·360/768/1440px 다크/라이트 검증. 명령: `PLAYWRIGHT_BROWSERS_PATH=/private/tmp/pubg-droplog-playwright PLAYWRIGHT_BASE_URL=http://127.0.0.1:3114 pnpm exec playwright test tests/e2e/event-map.spec.ts --grep 'timeline displays event distances|map pins and timeline|filter changes|event map [0-9]+px'`.
- 변경 파일 ESLint·Prettier·`pnpm typecheck` 통과. 전체 앱 E2E와 생산 빌드는 다시 실행하지 않았다.

## 2026-10-05 고해상도 맵

에란겔·미라마·태이고·론도의 공식 8192×8192 PNG를 같은 해상도의 WebP 품질 90으로 변환했다. [원본 URL·커밋·해시와 변환 명령](map-assets.md)을 기록했다. 기존 819×819/900×900 이미지는 홈·목록·헤더와 사건 지도의 첫 화면에 유지하고, 사건 지도 첫 확대 시 고해상도 한 장만 요청한다. 디코딩 성공 전이나 요청 실패 시 기존 이미지를 유지하며, 초기화 후에도 이미 로드된 고해상도를 사용한다.

| 맵     | WebP bytes | 기존 이미지와 프레임 상관계수 |
| ------ | ---------: | ----------------------------: |
| 에란겔 | 12,799,522 |                        0.9661 |
| 미라마 | 18,475,762 |                        0.9989 |
| 태이고 | 13,948,846 |                        0.9706 |
| 론도   | 20,008,266 |                        0.9780 |

- 네 PNG의 SHA-256을 공식 Git LFS 포인터와 대조했다. 전체 프레임을 256×256 회색조로 비교한 ±4px 검색의 최적 오프셋은 네 맵 모두 (0, 0)이었다. 이 비교는 큰 자르기·이동 여부 확인이며, 최신 게임 지형이나 센티미터 단위 좌표 정합성을 보증하지 않는다. 론도 좌표 지원 범위는 확장하지 않았다.
- 네 WebP를 로컬 디코딩했고 생산 빌드의 파일 해시가 원본 WebP와 일치함을 확인했다. 임시 생산 Nitro 서버에서 네 파일 모두 HTTP 200·`image/webp`·브라우저 `naturalWidth/naturalHeight = 8192`를 확인했다.
- 변경 컴포넌트·메타데이터·E2E의 ESLint, `pnpm typecheck`, `pnpm build`, `git diff --check` 통과.
- `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3113 pnpm exec playwright test tests/e2e/event-map.spec.ts`: **19개 통과, 15.7초**. 기존 17개와 새 지연 로딩·실패 대체 검증 2개다. 확대 전 요청 없음, 다운로드 대기 중 미리보기 유지, 실제 8192px 전환, 선택·초기화 후 고해상도 유지, 실패 시 반복 요청 방지를 확인했다.
- 에란겔의 같은 구역을 전체 폭의 1/16로 잘라 480px에 표시한 브라우저 비교 화면에서 건물·도로·지형 디테일 개선을 확인했다. API 응답은 합성 fixture이며 외부 PUBG 호출·DB 쓰기·공개 배포는 수행하지 않았다. Safari/iPhone 실기기와 최대 확대의 기기별 메모리·성능은 별도 검증 범위다.

## 2026-10-05 마우스 휠 확대

초기 휠 구현은 지도 위 수직 휠로 커서 위치를 기준으로 1~4배 연속 확대·축소를 제공했다. pixel/line/page 단위를 정규화하고 급격한 입력을 제한한다. 지도 안에서는 처리한 휠의 페이지 스크롤을 막으며 Ctrl/Meta 조합과 수평 전용 휠은 소비하지 않는다. 버튼·키보드·드래그 조작을 유지한다.

- 변경 컴포넌트·테스트 파일 ESLint, `pnpm typecheck`, `pnpm build` 통과.
- 임시 생산 Nitro 서버에서 `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3112 pnpm exec playwright test tests/e2e/event-map.spec.ts`: **17개 통과, 11.9초**. 기존 지도 14개와 새 휠 회귀 3개이며 전체 앱 E2E 재실행은 아니다.
- 실제 `page.mouse.wheel`로 확대·축소 후 커서 아래 이미지 좌표, 선택 이벤트, 페이지·지도 컨테이너 스크롤 보존을 확인했다. 합성 WheelEvent로 단위별 입력, 1~4배 경계, Ctrl/Meta·수평 휠 처리를 확인하고 지도 밖 실제 스크롤도 검증했다.
- API 응답을 합성 fixture로 제공한 UI 검증이며 PUBG 외부 호출·DB 쓰기는 수행하지 않았다. 기존 서버·분석기·DB 코드는 변경하지 않아 해당 단위·통합 테스트를 중복 실행하지 않았다.

같은 날 확대 상한을 **16배**로 높이고 버튼·휠·키보드가 같은 상수를 사용하도록 통일했다. 변경 파일 ESLint·typecheck 및 개발 서버의 확대 관련 Chromium **4개를 통과했다(9.5초)**. 16배에서 확대 버튼 비활성화, 축소 후 15.5배, 키보드 확대 시 16배 복귀, 휠의 상·하한과 기존 드래그·초기화를 확인했다. 이 추가 검증도 합성 API 응답을 사용했으며 전체 E2E나 생산 빌드를 다시 실행한 결과는 아니다.

## 사건 지도

2026-10-04 사용자 요청으로 사건 위치 지도를 추가했다. 역할별 위치를 분석 버전 2 JSONB에 저장하며 기존 버전 1의 좌표 없는 이벤트도 읽는다. DB 구조 변경은 필요하지 않다. `POST /api/reports/:reportId/upgrade`는 기존 기록을 수정하지 않고 새 버전을 생성·재사용한다. 생성·재시도와 5회/분 제한을 공유하며 재사용도 한 번으로 계산한다.

### 좌표와 이미지 근거

- [공식 Location 문서](https://documentation.pubg.com/en/telemetry-objects.html#location)의 왼쪽 위 원점·센티미터 단위·맵 범위를 사용한다. 현재 이미지가 있는 에란겔·미라마·태이고는 한 축 816,000 cm를 전체 이미지의 0~100%로 변환한다. x/y의 0을 유효한 좌표로 보존하고 음수·비유한 값·확인된 범위 초과는 제외한다. z는 음수 고도를 허용한다.
- 피해자·소생 대상의 당시 위치를 기본 핀으로 사용한다. 선택한 사건의 행위자, 킬 획득자·기절 유발자·마무리 공격자 역할을 구분하며 어시스트 ID만으로 위치를 만들지 않는다. 좌표 오류만으로 사건 전체를 삭제하거나 분석 품질을 낮추지 않는다.
- [공식 맵 이미지](https://github.com/pubg/api-assets/tree/master/Assets/Maps)의 `Erangel_Main_Low_Res.png`, `Miramar_Main_Low_Res.png`, `Taego_Main_Low_Res.png`와 사용자 제공 이미지의 전체 프레임을 비교했다. 모두 819×819이며 256×256 회색조 비교의 동일 위치 상관계수는 각각 0.9666/0.9996/0.9713이었다. ±4px 이동 검색의 최적 오프셋은 모두 (0, 0)이었다. 검증한 해상도에서 눈에 띄는 자르기·이동이 없다는 근거이며, 센티미터 단위의 지리 정합성을 보증하지 않는다. 지도 UI는 이미지를 자르지 않는다.
- 론도(`Neon_Main`)의 공식 좌표 범위는 확인되지 않아 이미지만 제공한다. 이미지나 기준이 없는 맵은 타임라인을 유지하고 안내를 표시한다. 이동 경로·사격 방향·안전구역을 추정하지 않는다.

`MAP_REPORT_ID='<기존 실제 리포트 UUID>' pnpm validate:map`으로 기존 카카오 랭크 스쿼드 에란겔 한 경기를 실제 PUBG 데이터에서 다시 분석했다. 결과는 `ready`, 전체 **607/607개**와 기본 주요 사건 **21/21개**에 유효한 대상 좌표가 있었다. 생성·저장 및 보존/재사용 확인은 **537 ms**였으며 기존 버전 1 객체 보존과 두 번째 요청의 동일 버전 2 ID 재사용을 확인했다. 원본 텔레메트리·키를 저장소 파일이나 로그에 남기지 않았다.

맵 이미지 추가 시 네 원본은 이미 WebP 인코딩이어서 내용 변환 없이 `public/maps/{erangel,miramar,rondo,taego}.webp`로 옮겼다(합계 766,870 bytes). 생산 서버에서 네 이미지 HTTP 200·`image/webp`와 디코딩을 확인했다. 홈·목록·저장된 실제 리포트를 360/768/1024/1440px × 다크/라이트로 검사해 가로 넘침·브라우저 예외·hydration 경고가 없었다. 카드·공유 버튼 최소 44px, 32자 닉네임도 확인했다. 당시 대표 대비는 다크 muted/card 6.91·primary/background 11.92, 라이트 7.73·4.81이었다. 지도 이미지 연결에 쓴 합성 응답을 다른 맵의 실제 경기 검증으로 간주하지 않는다.

### 초기 구현에서 해결한 문제

1. 앱 Zod 4와 SDK Zod 3을 Nitro가 외부 패키지 `zod` 하나로 합쳐 생산 API가 실패했다. `nitro.externals.inline: ['zod']`로 각 해석본을 번들에 포함하고 실제 생산 경로를 재검증했다. 빌드 성공만으로 API 성공을 판정하지 않았다.
2. SDK의 엄격한 match schema가 통계 누락을 거부했다. `ZodError`에만 공식 match 호환 요청을 허용하고, 네트워크·401·403·429·timeout에서 재요청하지 않음을 검증했다. 상세 근거는 [SDK 검토](sdk-review.md).
3. 피해량 비중의 0~100 값에 UI에서 100을 재차 곱하던 부분을 수정했다.
4. SSR 이후 hydration 전에 입력한 값이 사라질 수 있어 준비 완료까지 검색을 비활성화했다. ofetch의 기본 GET 재시도가 409를 가리므로 API 호출에 `retry: 0`을 지정했다.
5. 메타데이터 요청과 분석이 별개 30초 예산을 쓰지 않도록 요청 시작 기준 deadline을 사용하고, DB 쿼리 timeout을 고려해 부분 결과 저장 시간을 남겼다. 이전 페이지 결과는 DB 일괄 조회로 재사용한다.
6. 공유 메타데이터 다운로드는 각 요청의 참조를 추적하며 마지막 대기자가 취소했을 때만 실제 전송을 취소한다.
7. 더 보기 후 이전 묶음의 실패를 복구하지 못하던 UI를 수정했다. 실패 묶음 커서를 추적하고 복구 후 가장 멀리 읽은 범위의 합계·다음 커서를 유지한다.
8. 재시도에서 최신 match의 공식 통계를 사용하도록 수정했다. 팀/참가자 관계가 달라지거나 확인된 통계·순위가 null로 퇴행하면 기존 리포트를 보존한다.
9. 빈 피해 대상과 비어 있는 killer 피해 정보 때문에 환경 사망을 오해할 수 있던 처리를 수정하고 회귀 테스트를 추가했다.
10. 순수 벤치마크의 `tsx` CLI가 sandbox의 IPC 소켓 제한에 걸려 `node --import tsx`로 실행 경로를 바꿨다. 벤치마크 재실행은 통과했다.
