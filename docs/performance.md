# 성능 측정 기록

2026-10-04 로컬 환경에서 수행한 **과거 측정 기록**이다. 문서 정리 과정에서 벤치마크나 테스트를 다시 실행하지 않았다. 합성 분석기 수치는 사건 지도 도입 전 **분석 버전 1**의 결과이며, 현재 버전 2의 성능으로 해석하지 않는다. 실제 PUBG 경기 측정과 자동 검증 결과는 [검증 기록](validation.md)에 따로 남긴다.

## 측정 환경

| 항목           | 측정 당시 환경                                         |
| -------------- | ------------------------------------------------------ |
| CPU / 메모리   | Apple M1 Max, arm64 / 64 GiB                           |
| OS             | macOS, Darwin 24.6.0                                   |
| Node           | v24.21.0                                               |
| 분석 동시 실행 | 1개                                                    |
| HTTP 측정 서버 | 로컬 생산 Nitro Node 서버                              |
| HTTP 측정 DB   | Docker Compose PostgreSQL 17.6, 로컬 `127.0.0.1:55432` |

순수 분석기 벤치마크는 DB를 사용하지 않았다. 아래 HTTP 측정은 같은 머신의 loopback 요청이며 운영 호스팅이나 인터넷 지연을 포함하지 않는다.

## 분석 버전 1 합성 벤치마크

당시 [벤치마크 스크립트](../scripts/benchmark.ts)는 일반 fixture를 워밍업 후 10회, 큰 fixture를 1회 분석했다. 큰 입력이 압축 해제 기준 32 MiB보다 작고, 정규화 결과가 20,000개로 제한되며 `EVENT_LIMIT_EXCEEDED`를 가진 `partial` 리포트가 되는지 함께 확인했다.

### 입력과 결과 범위

| 항목           | 일반 fixture |                                  큰 fixture |
| -------------- | -----------: | ------------------------------------------: |
| 입력 이벤트    |        119개 |                                    25,001개 |
| 입력 JSON 크기 | 34,137 bytes |              23,950,056 bytes, 약 22.84 MiB |
| 정규화 이벤트  |        116개 |                                    20,000개 |
| 품질           |      `ready` |                                   `partial` |
| 누락 안내      |         없음 | `EVENT_LIMIT_EXCEEDED`, 제외 이벤트 5,000개 |

### 측정 이력

| 측정 시각                              | 일반 fixture 중앙값 / p95 | 큰 fixture 분석 시간 | 프로세스 최대 RSS |
| -------------------------------------- | ------------------------: | -------------------: | ----------------: |
| 2026-10-04 11:09:38 UTC (20:09:38 KST) |            1.16 / 3.96 ms |             86.22 ms |        250.36 MiB |
| 2026-10-04 20:18 KST                   |            0.93 / 1.88 ms |             91.17 ms |        250.36 MiB |

중앙값 열은 당시 스크립트가 출력한 `medianMs`다. 10개 표본을 정렬한 뒤 가운데 두 값 중 뒤쪽 값을 사용한다. 큰 fixture는 실행별 한 번만 측정했으므로 p95가 아니다. 첫 실행의 시작 RSS는 95.72 MiB였고, 20:18 실행의 최대 RSS 원시값은 262,520,832 bytes였다.

최대 RSS에는 fixture 생성, JSON 직렬화로 입력 크기 계산, 정규화와 출력 스키마 검증이 포함된다. 분석 함수 하나의 추가 메모리로 해석하면 안 된다. 분석 시간은 순수 동기 분석기 범위이며 외부 다운로드, 전송 계층의 JSON 파싱, HTTP, DB, 브라우저를 포함하지 않는다. 저장 리포트 API나 30초 요청 전체 예산의 검증 근거로 사용하지 않는다.

### 현재 코드에서 다시 측정할 때

```sh
pnpm benchmark
```

위 명령은 **현재 체크아웃**을 측정한다. 현재 [분석기](../server/domain/report.ts)는 버전 2이고 [데모 fixture](../server/fixtures/demo.ts)에 역할별 좌표가 추가되어, 일반 입력 크기와 분석 결과 구조가 위 버전 1 기록과 다르다. 큰 fixture에는 좌표가 없으므로 지도 좌표가 채워진 대용량 입력의 비용까지 측정하는 것은 아니다.

현재 스크립트의 stdout JSON은 측정 환경, 입력 JSON 크기, 정규화 이벤트 수, 시간, 프로세스 최대 RSS를 출력한다. 버전 2 재측정값은 이 문서에 아직 기록하지 않았다. 실행 환경과 검증 명령은 [개발 가이드](development.md)를 따른다.

## 저장 리포트 HTTP 조회 이력

로컬 생산 Nitro와 로컬 PostgreSQL에서 저장된 듀오 리포트를 동시성 1로 100회 조회했다. 모두 저장된 결과를 읽는 GET 측정이며 실제 PUBG 다운로드·신규 분석 지연이 아니다.

| 측정 단계                             |      p95 |  중앙값 |
| ------------------------------------- | -------: | ------: |
| 초기 MVP 최초 측정                    |  9.14 ms | 5.76 ms |
| 초기 MVP 생산 코드 재측정             |  8.30 ms | 5.55 ms |
| 초기 MVP API 원문 canary 검사 추가 후 | 26.53 ms | 7.92 ms |
| 사건 지도 추가 후 마지막 생산 smoke   |  6.90 ms | 5.50 ms |

모든 회차에서 로컬 p95 목표 500 ms 이내였다. 회차별 조건과 변동이 있으므로 이 표만으로 버전 간 성능 개선을 주장하지 않는다. 각 실행의 검증 맥락은 [검증 기록](validation.md)에 있다. 운영 SLA, 동시 부하, 외부 네트워크 성능은 별도 확인 대상이다.

## PostgreSQL 검증과 실제 경기 측정

DB 생성·전용 테스트 DB 설정·실행 방법은 [PostgreSQL 통합 테스트](development.md#postgresql-통합-테스트)를 따른다. 테스트는 `_test`로 끝나는 전용 DB에서 실제 마이그레이션을 적용하며, 자신이 생성한 식별자의 데이터만 정리한다.

초기 MVP에서는 20:08 KST에 9개 테스트를 844 ms, 일괄 조회 검증 추가 후 20:17 KST에 10개를 998 ms에 통과했다. 이후 사건 지도 변경에서 좌표 호환 검증을 추가했으며, 현재 기록된 12개 테스트 결과와 세부 범위는 [검증 기록](validation.md)에 있다. 이 문서의 초기 결과를 최신 실행 결과로 사용하지 않는다.

카카오 랭크 스쿼드 5경기의 실제 다운로드·분석에서는 전체 프로세스 최대 RSS 526.69 MiB를 기록했다. 위 합성 분석기와는 측정 범위가 다르며, 실제 생성 시간·다운로드 크기는 [실데이터 검증 기록](validation.md#t07-실제-데이터출시-경계)을 참고한다. 실제 일반전·다른 모드·Steam과 여러 프로세스에서 키를 공유하는 상황은 미검증이다.
